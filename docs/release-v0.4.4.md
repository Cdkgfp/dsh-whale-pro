本版本修复后端认证降级及相关安全问题，建议使用旧版的用户更新。

## 安全修复

- 所有 `/dsh-whale/*` 路由强制通过宿主 `connection.requestRejection(req)` 准入。认证接口缺失、服务查找失败、调用异常或返回值不符合约定时拒绝访问（HTTP 503），不再退回仅凭回环地址和来源判断；保留宿主返回的 401/403。
- 本机写操作同时检查真实连接对端与 Host；显式配置的远端管理主机也必须先通过宿主认证。
- 为接口设置 HTTP 方法白名单，角色删除、置顶、泡泡图片上传等操作不接受 GET/HEAD，错误方法返回 405。
- 凭据操作限于内置厂商名称和 `DSHW_` 开头的自定义名称，不再使用删除结构化凭据记录的兼容分支。内置 DeepSeek 可以更新密钥，但不能覆盖厂商、凭据名或接口地址。
- 校验模型 ID 和厂商名称，并递归净化配置键，修复对象原型污染。
- 加固元数据及映射 IP 地址校验，检查并固定 DNS 解析结果；余额、额度、探活请求不跟随重定向，响应体限制为 2 MiB。
- 清理会拼接出 `undefined...` 文件名的旧运行数据路径，修正删除密钥失败时仍提示成功的问题。

## 升级说明

- DSH 必须提供宿主认证准入接口；缺少该能力的旧宿主需要升级。`DSHW_TRUSTED_HOSTS` 不再提供兼容放行，`DSHW_ADMIN_HOSTS` 不能绕过认证。
- 自定义凭据名请使用 `DSHW_` 前缀。原先使用其他名字的模型，需要在设置中改名并重新配置密钥；插件不会自动删除旧凭据。
- 本机模型和内网网关仍可使用。自定义接口应填写最终地址，不依赖 HTTP 重定向。
- 更新后需完全退出 DSH（含托盘）并重新打开，后端修复才会生效。
